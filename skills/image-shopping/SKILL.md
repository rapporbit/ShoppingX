# 图搜选购

## 顺序：先看图，再拆意图

有图的轮次，`image_understand` **先于 `planner` 预跑**（开局预置由控制面负责，见
`HarnessAgentAdapter._prefill`）。它把图读成结构化文本：品类 / 颜色 / 材质 / 风格 + 检索词，
再把这些结论**并进 `planner` 的 intent**。

**图片本身永远不进主 loop 的 messages。** 主模型（`LLM_MAIN`）是纯文本的，多模态块塞进去
只会报错或被静默忽略；而且一张几百 KB 的图会挤进后续**每一轮** prompt。所以图被关在
`image_understand` 内部——工具里调 VL 模型（`LLM_VISION`），主 loop 只看见它吐出的文本结论。

## 能力边界：这不是以图搜图

**是「看图说话再搜文本」**：VL 模型把图翻译成检索词，检索词并入既有的 BGE-M3 文本召回链路。
所以找到的是**同品类同属性的相似品**，不是「一模一样的那只」。

- 对「想买类似这种风格的东西」够用 —— 大方向说得出来。
- **同款复刻做不到，别宣称**。用户说「就要这个同款」时，如实说明这是按图里的品类和属性找
  相似款，并把识别出的属性摊开给他确认（「深棕、翻盖、真皮、通勤风的单肩包，对吗」）。
- 图不可读（改名的 PDF、损坏文件）或 VL 未启用时**如实说**，不要凭文件名编造内容。

## 检索词怎么写

1. **优先出英文**。商品库正文以英文为主，英文词打英文库更准 —— 虽然 BGE-M3 本身跨语言，
   但同语种检索的召回质量实测更稳。
2. **`item_search(query=...)` 只放品类核心词**（`leather shoulder bag`、`laptop backpack`）。
   风格 / 场景 / 人群 / 正式度词（`vintage`、`commute`、`men`、`formal`）**不要堆进 query** ——
   它们会把同场景的其他品类一并召回、稀释目标品类（实测 `formal dress watch men business`
   召回的大半是西装皮鞋）。
3. **风格词交给 `item_picker(prefer_keywords=...)` 加分**，在精挑阶段起作用。图里读出来的
   颜色 / 材质 / 风格几乎全该走这条路，而不是走 query。
4. 图里能读出**硬约束**（明显的尺寸标注、容量、接口类型）时才写进过滤参数；模糊的观感
   （「看着挺大」）不是硬约束。

## 图与文字冲突时，文字优先

用户经常「图 + 一句话」一起给：「照这个找，但预算 300、别要塑料的」。

- **预算 / 排除 / 平台 / 收货国这类硬约束以文字为准**，图只贡献品类与观感属性。
- 图里的东西明显超出文字预算时，不要因为「图长这样」就把超预算的推上来 —— 如实说
  「图里这类的价位普遍在 X 以上，你的 300 能买到的是这些」，再给候选。
- 用户后续轮改口（「颜色换成黑的」），以**最新一轮文字**为准，图的结论只作背景。

## 收尾

清单里要**回扣图**：每件写清它在哪些属性上贴合参考图（品类/颜色/材质/风格），哪些不贴合。
不要只说「跟你的图很像」——那句话没有信息量，也没法验证。
