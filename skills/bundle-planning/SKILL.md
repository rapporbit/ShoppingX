# 槽位规划：一套齐 vs 多品类并列

## 两种形态，别混

planner 把需求拆成**槽位**（slot），槽位带**形态**（`SLOT_MODE_bundle` / `SLOT_MODE_parallel`），
与槽表同生命周期、一起落盘 `bundle.json`。两者共用槽位登记 / 打标 / 分组精排 / 报告结构，
**只有最后那一步选择规则不同**：

| | `bundle`（一套齐） | `parallel`（多品类并列） |
| --- | --- | --- |
| 语义 | 凑一套、要配套 | 各买各的、互不相干 |
| 触发 | 「新生入学一套」「露营装备一套」「旅行三件套」 | 「跑鞋 + 降噪耳机」「顺便再看看背包」 |
| 预算 | **总预算**（Σ 到手价 ≤ 预算） | **每件上限**（不求和） |
| 选择 | MCKP 组合优选 | 每槽独立取 top N |
| 能砍槽 | optional 槽可整槽放弃 | **绝不砍类**——用户明说要的每一类都得给 |

**MCKP 不能拿去跑并列**：它为了凑总预算会整槽放弃 optional 槽，那在「一套齐」里是对的，
在并列需求上就是把用户明说要的一类悄悄弄丢。

## 框定：缺的事实写成假设，别拿来当问题

五件事决定一份方案长什么样：**要办成什么、给谁、在哪、什么时候要、预算多少**。需求和
`<user_long_term_memory>` 里有的就拿来用；**没有的每一条都写成一个取整的假设**
（「按一个人用估的」「没说预算，按中档挑」），摆在方案里让用户一个词就能改。
**槽内的取舍**（某样要买几个、某个槽要不要）是写在那个槽上的假设，不是把整份方案扣住不发的理由。

只有**槽本身就拿不准**时才先发框架：用户问「从哪儿开始」，或者这套东西有不止一种拆法。
那一轮只给槽和预算分摊、不带商品（**唯一一次不带商品**），同轮用 `ask_user` 把最影响拆法的
那一个问题连同 options 发出去，商品下一轮再给。**问题不能脱离方案单独发出去**。

预算给了就**按槽取整分摊并展示出来**（「书桌 ~$120 / 台灯 ~$40 / 收纳 ~$40」），
扛主要作用的槽分大头。

## 组合优选（只在 bundle 形态）

Multiple-Choice Knapsack：**essential 槽必选一件**、optional 槽可整槽放弃，约束
`Σ 有效价 ≤ 总预算`，目标 `max Σ 分数`。槽 ≤ 6 × 每槽 top5 → 穷举即可（数万组合、毫秒级），
不需要近似算法。

**不可行时如实报**：给最省的那组组合 + 超支多少，**绝不静默超预算**，也不要偷偷把某一槽
换成明显不合用的便宜货来凑数。

## 检索：一槽一条 `item_search(slot=槽名)`

多个槽位是「能并行」在本仓真正成立的来源（与启用平台数无关，任何配置下都成立）。

- **一个槽一条 `item_search`，同轮一次性发多条**，框架看到多个 tool_call 就并发跑。
- `slot` 传槽名，`query` 只写这一类的核心词——候选按 `slot` 确定性打标归槽（另有关键词归槽
  兜底）。planner 没拆出槽表时，传了 `slot` 也会自动补登成并列槽，不用先回头重拆。
- **用户说某一槽他已经有了 → 那一槽标「已有」，不发检索、不给商品**，但仍留在方案里占位，
  预算分摊也把它的份额让给别的槽。
- 一个槽**只有在本会话真的检索回了东西**才算配齐；召回空的槽先按「换核心词再搜一次」的规矩
  重试，重试后仍空才算缺口。某槽唯一的候选超了它那份预算，**就留在那个槽上并标超支**，
  不要悄悄换成别的槽的东西。

## 收尾

- **「是不是槽位轮」由机制判**（会话里登记的槽 ≥ 2），不由你自报。`item_picker` 会自动按槽
  分组、每槽用自己的干净 `slot_query` 分批精排——所以**不要**把几个品类的词堆进同一个
  `query`，那会让某一类屠版。
- `shopping_summary` 拿到的是**分配表**（哪槽花了多少、砍了谁、缺了谁），照它写：
  - 每槽一件、紧凑排版；
  - 砍掉的 optional 槽要**明说砍了**和为什么（预算不够）；
  - 某槽召回为空要**明说缺货**，不要拿别槽的东西顶上。
- 组成有歧义时（「一套」到底含不含书桌）用 `ask_user`，它支持**可点选 options**，
  比让用户打字快得多。用户删掉某个槽 → 记 `declined`，后续轮不再补搜它。

## 给过一份之后再改

**改一个槽只动那一个槽**：其余的槽——包括用户前面几轮自己调过的——原样不动，不要借机重挑一遍。
改完**重出整份方案**，别只回一句「已换成 X」让用户自己在脑子里拼。
