# 撤回长期偏好

## 先分清：撤回记忆 vs 本轮不满意

`forget_preference` 动的是**跨会话的长期记忆**，不是本轮的筛选条件。三种听起来像、其实不是的情况：

| 用户说的话 | 该做什么 |
| --- | --- |
| 「别再记着我不要塑料了」「把你存的那条偏好删掉」 | **调 `forget_preference`** |
| 「这次预算改成 500」「这几件都不喜欢，换一批」 | 不调。本轮条件变了，重新检索即可 |
| 「我现在反而喜欢塑料的了」 | **不调**。记忆管家在会话结束时按 recency-wins 自动用新说法顶掉旧条目（`keys_to_supersede`），手动删一遍是多余动作 |

判据是一句话：**用户要动的是「你记住的东西」，还是「这次给我找的东西」**。只有前者才调。

## 怎么挑准要删的那条

`<user_long_term_preferences>` 块里每条长这样：

```
- [dedup_key] 内容（归类，极性）
```

- **优先传 `key=`**，值就是方括号里那个 `dedup_key`，原样抄。这是精确删除，删哪条一目了然。
- 用户说得笼统、对不上任何一条 key 时，才传 `description=` 走关键词模糊匹配（content 与关键词互为子串即命中）。
- `polarity` 只在需要限定一侧时传：同一个词可能同时存在 like 和 dislike 两条（「喜欢纯棉」与「不要纯棉混纺」），用户只要删其中一侧时用它。

匹配是**确定性子串匹配，不做语义猜测**——宁可漏删也不误删。删错一条用户没要求删的偏好，比没删掉更糟：他不会知道，但后面每一轮推荐都跟着偏。

## 删不到就如实说

返回里 `count=0` 且 `note` 是「未找到匹配的偏好」时，**不要说「已经忘掉了」**。正确的回话是告诉用户没找到匹配的条目，并把当前记着的相关偏好念给他听，让他指认哪条。

匿名会话（未登录）压根没有长期偏好，`note` 会说「匿名会话没有可撤回的长期偏好」——这时如实说明需要登录才有跨会话记忆，别假装删过。

## 它不是终结工具

删完**继续跑**，该检索检索、该收尾收尾。收尾仍然只能由 `shopping_summary` 或 `chat_fallback` 给出。

如果用户这一轮只是来删记忆、没有购物意图（「把你记的偏好都删了」），删完用 `chat_fallback` 收尾，说明删了哪几条。一次只处理用户明确点到的条目，**不要因为「看着像过时的」就顺手多删**。
